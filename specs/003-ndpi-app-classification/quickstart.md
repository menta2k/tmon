# Quickstart / validation guide (feature 003)

## Prerequisites

- Feature 002 working, with `[capture] enabled = true`.
- For the real-classifier scenarios (V2–V4, V9): nDPI 6.0 built and installed (`just dpi-build`, which builds the pinned tag into `backend/dpi/target/ndpi/`), then `cargo build --release --manifest-path backend/dpi/Cargo.toml`.
- The fixtures, generated by `just fixtures-apps`, are written to `backend/tests/fixtures/capture/apps_*.pcap`.
- CI-only scenarios use the fake classifier: `cargo build -p tmon-dpi-client --example fake_dpi`.

## Scenarios

| # | Scenario | How | Expected |
|---|---|---|---|
| V1 | Disabled = unchanged (SC-007) | Run feature 001 and 002 suites + `bench-ingest.sh` without `[dpi]` | All pass. No `tmon-dpi` process is started. `/status.dpi = {"enabled": false}` |
| V2 | Apps without names (US1, SC-002) | `[dpi] enabled = true`. Replay `apps_mix.pcap` (BitTorrent, WireGuard, OpenVPN, STUN+RTP, Steam A2S, RDP; both directions) to 37008, then `apps_flows.pcap` to the flow collector | ≥ 90 % of the fixture connections show the expected `app` and category with `confidence = detected`. `/traffic/breakdown?by=app` lists them |
| V3 | Precedence (US1 #3, #5) | Replay `apps_zoom_tls.pcap` (TLS SNI `zoom.us`, also recognized by nDPI). Add a user rule `app = [Zoom] → Work` | `remote_host = zoom.us` with `remote_host_source = tls`, `app = Zoom`. The category is Work once the user rule exists. Without that rule, the hostname rule wins |
| V4 | Guess vs confident (US1 #4) | Replay `apps_port_only.pcap` (UDP 51820, payload that is not WireGuard) | If nDPI only guesses by port: `app_confident = false`, rule confidence `inferred` |
| V5 | UI (US2) | Flows → filter `app = BitTorrent`; export CSV; host drill-down; rule editor `app` picker; "Test rule" | The filter works; the CSV has `app,app_confident`; the drill-down lists top apps; the picker lists the catalog; the test shows matches |
| V6 | Crash and restart (US3, SC-004) | With the fake classifier in `crash_after=1000` mode, replay `mixed-home.pcap` + `apps_mix.pcap` in a loop for 2 min | 0 flow drops. `restarts_total` rises. State returns to `running` within 30 s. After 5 crashes in 10 min: `failed` + `dpi_failed` warning |
| V7 | Version and missing binary (US3, US4) | (a) `binary = "/nonexistent"`; (b) fake classifier `--proto-version 2` | (a) `dpi_not_found`, tmon serves normally; (b) `dpi_incompatible`, no restart loop |
| V8 | Overload (US3 #5) | Fake classifier `slow_us=2000`; `CAPTURE=1 CAPTURE_RATE=20000 DPI=1 bench-ingest.sh 10000 60` | `dropped_queue` > 0; `dpi_dropping` warning; 0 flow drops; tmon RSS ≤ 002 bound + 16 MB |
| V9 | Sandbox and memory (US4, SC-005) | Real classifier under the flood from V8 for 10 min; `cat /proc/<pid>/status` (`NoNewPrivs`, `Seccomp: 2`); in the classifier, `strace -f -e trace=network` shows no `socket()` | Classifier RSS < 256 MB. Seccomp is in filter mode, no network syscalls. The log lists the restrictions applied |
| V10 | IPC fuzz (SC-008) | `just fuzz-dpi 600` (both codec directions + `sidecar_packets`) | 0 crashes |
| V11 | Real network (SC-001) | After 1 day with the reply-direction rule applied: `by=rule` confidence shares versus the same day of the week with DPI off | "guessed" + uncategorized bytes reduced by ≥ 50 % |
